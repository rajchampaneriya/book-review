From HTTP noise to domain language

Review scorecard line: “Domain language, declarative — ◐ titles are behavioural; bodies are HTTP verbs, headers and SQL.” The titles promise behaviour; the bodies whisper client.post("/v2/bookings", headers={"Idempotency-Key": …}). This plan closes that gap for the Python stack: the spec starts reading like a story, and the transport plumbing moves one layer down, into drivers.

The translation ladder

feature Gherkin scenario “the client retries the identical booking”
step one sentence = one call client.retry_identical()
vocabulary boundary — HTTP, headers & SQL live only below this line
driver the translator httpx + psycopg, wrapped in domain verbs
repo code the service itself FastAPI app, BookSessionIdempotentService

A reader above the line never needs to know what POST means. Everything below the line never needs to know what the sentence says. Each layer has one job — that is why the plan is fixable in an afternoon.

Decompose the problem (Greg Tang: break it into friendly pieces)

One hard problem (an imperative test) bonds into three easy ones. Each phase of the plan below builds exactly one bond. No step asks two questions at once.
